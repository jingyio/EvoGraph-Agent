# Plan、AutoTool 自动图与并发执行

工具文档只补用途和主要返回字段，见 [简明目录](tool-catalog.md)；精确参数保留 JSON Schema，不新增冗长的输入来源、前置条件或错误说明。

## 流程与分工

1. `backend/gagent.py:build_data_plan` 调用规划角色，生成当前任务的数据获取子目标和依赖。每个子目标是显式 intent，不读取或要求模型内部思维链。
2. `backend/autotool.py:retrieve_tools` 用当前 intent 检索短工具描述，采用本地 BM25、英文词和中文二元组，召回 top-4。它是词汇检索，不是嵌入语义匹配，也不保证召回率。
3. 本地选择器按 BM25 分数与工具参数契约选择工具。有上游分页列表时优先选择单记录 `*Id` 读取，否则选择任务范围或分页读取；没有正分且可编译的候选时回退 ReAct。这个阶段不调用模型。
4. `backend/intent_graph.py` 按工具签名与依赖自动绑定分页及 `records[].id`，生成 foreach 节点，NetworkX 检查 DAG。工具契约声明主要输出字段；若上游列表已返回当前步骤需要的字段，编译器生成复用节点，不再逐条调用详情工具，并按实际记录数累计 `elidedToolCalls`。拒绝无上游列表、多个不明确列表、未知工具、越出候选和写入工具。编译器只支持当前任务库的无参、分页和单记录 ID 读取契约。
5. 依赖满足后的读取节点及遍历调用并发执行，模型使用本次观察计算并发布报告。整个图的调用记录以批次注入模型上下文，不为每次读取伪造一轮单步 thought。
6. 后续执行仍可通过 `request_tools(intent)` 更新当前子目标并重新召回工具，下一次模型请求使用更新后的工具集合。发布与算术工具始终可用。

Plan 产生一次真实模型请求；AutoTool 检索、图工具选择和契约编译均在本地完成，`graph` 阶段模型请求为 0。Plan 结构响应可修正一次，计入相同预算。规划、编译或执行失败时，保留成功观察并回退到完整工具集的 ReAct；所有规划成本和回退原因保留。原始错误记录没有被新运行覆盖。

每次实际工具调用保存规范化的工具名与参数签名。只有同任务对照与 AutoTool 两次运行均通过结构化评分时，页面才计算差异。主指标是总调用净减少和按工具名计数的少执行次数；精确参数签名只用于审计，因为分页大小或报告文本不同不应被误报为额外收益。页面分别支持 ReAct 对照和 Plan + ReAct 消融。DAG 中直接执行一次读取不算“跳过工具调用”；它只跳过模型逐步决定该读取的过程。只有基线对同名工具的执行次数更多，才计为少执行。

这是 G-Agent 思路下的独立 Plan、模型角色和有界调度实现，不声称完整复现某篇论文。当前自动图每任务生成，不等于从历史轨迹学习的 motif，也没有自动将本次图晋升到公共经验库。旧 OpenAPI 工具生成、历史读取图和负 motif 模块仍独立存在。

## 模型与并发配置

后端 `.env` 中现有 `LLM_MODEL` / `LLM_BASE_URL` / `LLM_API_KEY` 控制执行模型。新增可选 `PLANNER_MODEL` / `PLANNER_BASE_URL` / `PLANNER_API_KEY` 控制规划角色，未填写的字段继承执行配置。可配置小模型规划、大模型执行；界面只报告实际模型名称及是否不同，不凭名称猜模型规模。

HTTP 仍全部经过 `backend/model_client.py`，两角色均关闭 thinking，OpenRouter 同时关闭 reasoning。`phaseMetrics` 分别记录 plan、graph、execute 请求与 token，失败请求也计入总预算，不返回 usage 时标记不完整。

调度独立限制如下（仅针对新的 TaskRunner，不是所有旧 API 的全局资源限制）：

| 配置 | 默认 | 含义 |
|---|---:|---|
| TASK_RUN_CONCURRENCY | 4 | 同时执行任务数 |
| TASK_MODEL_CONCURRENCY | 4 | 两种模型角色合计请求并发 |
| TASK_READ_CONCURRENCY | 8 | 所有任务共享的读取并发 |

最多 32 个运行中或排队任务。排队等待与执行耗时分开记录。SQLite 只读操作在工作线程执行，使用独立证据上下文，完成后合并；报告等产物顺序执行。ReAct 基线收到批量读取调用时也可并发，不人为削弱基线。取消后已进入线程的只读操作可能短暂完成，但不会修改业务数据或继续写入运行上下文。

测试验证有界并发、跨任务状态隔离、阶段计量、排队/运行取消、动态分页、依赖顺序、检索、非法图拒绝和 ReAct 回退。这里只证明调度机制，尚未进行大规模吞吐压测。

## 使用

任务库 `http://127.0.0.1:5173/#taskbank` 新增 Agent 执行区，可选择 ReAct、Plan + ReAct 或 Plan + AutoTool DAG。可以切换任务连续提交，后台独立排队，查看 Plan、候选工具、读取图、分阶段 token、评分和回退。原先手工工具调试仍不调用模型。

```text
POST /api/taskbank/runs
{"taskId":"finance-payment_totals-01","strategy":"autotool"}

GET  /api/taskbank/runs
GET  /api/taskbank/runs/{id}
POST /api/taskbank/runs/{id}/cancel
```

完整结果保存在 `artifacts/taskbank-runs/<id>.json`。不读取 gold.json 或参考答案作为模型输入。三个模式使用相同任务、工具实现和评分器；后续对照须同时比较 Plan + ReAct，以区分模型规划、工具检索和图执行贡献。

### 当前本地图选择与工具消除消融

2026-09-10 使用同一任务 `tickets-unassigned-01` 对比 Plan + ReAct 与 Plan + AutoTool DAG。两次运行均通过相同的结构化事实与证据评分，报告文字不计入评分。图选择阶段完全本地执行，模型请求为 0。

| 策略 | 运行 ID | 模型调用 | 工具调用 | 输入 / 输出 token | 耗时 | 实际消除 |
|---|---|---:|---:|---:|---:|---:|
| Plan + ReAct | `32411880-8622-4ca0-a04a-704beb0e911c` | 5 | 8 | 10,590 / 834 | 18,131 ms | 0 |
| Plan + AutoTool DAG | `565cf6a5-7d65-490c-b4c8-1acf5c44527b` | 4 | 5 | 6,394 / 713 | 13,041 ms | 3 |

AutoTool 先执行 `tickets_list_issues`。该列表已经返回每条工单的 `state`，编译器因此把 `get_state` 编译为复用节点，直接读取上游 `records[].state`，没有执行以下三次详情工具：

```text
tickets_get_issue(issueId=4398)
tickets_get_issue(issueId=5896)
tickets_get_issue(issueId=5960)
```

AutoTool 的实际轨迹只包含一次列表读取、三次分派读取和一次报告发布，`elidedToolCalls=3`。这里的“消除”由同任务、同评分通过的两条规范化工具轨迹计算，并可在页面按工具名审计；不是把 DAG 直接读取或少一轮模型决策记作少调用。

本次 AutoTool 的 Plan 首次结构格式不合格，规划阶段发生一次修正，因此 `controlErrors=1`、Plan 请求为 2，相关 token 和耗时都保留在指标中。即使包含这次额外成本，总工具调用仍从 8 降至 5。另一个诊断运行 `a1d74d84-4380-4ed4-a9a5-3c757c228acb` 没有触发复用：规划器加入了与字段目标无关的表述，编译器无法可靠证明上游字段满足要求，因此仍执行 8 次工具调用。这个反例说明当前收益取决于 Plan 是否明确表达所需字段，不能据单次成功运行外推平均收益。


## 在线 Graph RSI

新增 `graph_rsi` 策略复用持久化计划和读取图，利用正常训练/验证任务积累证据；有依据的优化或失败恢复产生后继版本，不额外运行影子任务。原 `autotool` 策略保留为每任务规划的对照。协议、计量与局限见 [在线进化](online-evolution.md)。
