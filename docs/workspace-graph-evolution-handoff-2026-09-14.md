# 工作区完整图复用与反馈进化：执行规格

日期：2026-09-14。讨论核对基线：`301f14b`。这是用户确认的下一阶段目标和执行规格，
不是已实现能力或新的实验结果。本讨论 session 只更新交接文档；执行 session 是代码写入者。

## 1. 用户确认的目标

- 普通上传工作区默认关闭学习可以保留，但要能只读检索经过审核的历史结构。
- 用户文本与当前附件 schema 应能匹配历史图，不能依赖预先提供的 family/template。
- 可复用图应覆盖读取、确定性计算以及已有本地产物写入，跳过已确定工具的选择和参数填写。
- 下一版 48 个 train 工作包对照必须实际启用工作区图反馈修订，并展示真实修订与后续使用。
- 效率、效果、可靠性和可展示性仍是验收重点。约 30% token 优化是目标，不能改变分母、
  放宽校验、挑选结果或伪造图代际来达到目标。

## 2. 当前代码中需要改变的边界

- `OnlineEvolution.context_key` 的精确指纹可保留为查询加速，但当前 Workpack 使用
  `template=workpack:<workflow>`，不能把它当作用户文本语义匹配的证据。
- `build_data_plan` 只规划读取，`ordered_nodes` 和通用编译器只允许 read；复杂计算和本地
  artifact 的工具选择/参数仍由执行模型生成。
- `OnlineEvolution.observe` 对 workspaceTable 图提前返回，跳过后继修订。必须替换为
  工作区专用的验证/修订路径，而非仅删除 return 后调用不兼容的列表/详情编译器。
- 默认上传 runner 的学习开关与经验路径独立。需区分只读的已审核经验、实验可写经验、
  用户文件/运行状态。不要把 V17 实验数据、旧观察、gold 或用户附件拷入共享模型上下文。

## 3. 文本匹配与当前任务绑定

实现以下行为，不另建完整 Agent 框架：

1. 按场景、当前工具契约、可绑定表槽/字段类型检索候选；使用已有本地检索组件做短名单。
   不以 family/template/workpackId 作为语义选择的答案。这些字段只用于实验分组和审计。
2. 精确命中也要验证当前任务与历史工作流的适用条件、交付要求及参数来源。
   不能因为声明了同一个 workflow 就沿用旧阈值、日期、排序或筛选字面量。
3. 对无法本地可靠判断的语义，允许一次有界的结构化选择/绑定模型请求。尽量与正常
   Plan 阶段合并，返回复用选择与当前槽值，或返回新 Plan；记录失败选择和 Fallback 成本。
   不为每个工具再调用一次模型填参。模型配置仍只经 model_client，不读隐藏 thought。
4. 参数必须绑定到当前请求、当前 schema、当前读取/计算结果；缺字段、类型不符、歧义、
   未支持运算或任务要求超出图覆盖时，明确拒绝该部分复用并转正常模型流程。
5. 记录候选 ID、来源 run、匹配依据、拒绝原因、当前语义槽、绑定事件及真实请求/token。
   “免完整 Plan”不等于“零匹配模型调用”，不能把槽数量换算成节省请求数量。

## 4. 从读取图扩展到计算与本地产物图

沿用 dict 图和现有 Tool/schema/context，不建设大型新 IR。为新工作区图使用明确协议版本，
不要通过放开所有 effect 破坏旧读取图/TinyEdge 的边界。

优先编译实际正常训练中使用的关键确定性 compute，如键控对账、聚合、排序/期间计算。
保留实际工具名，并为嵌套参数提供受约束的结构绑定：

- workspaceTable：当前表槽 -> 当前工作区 tableId。
- result：当前上游工具输出路径 -> 当前输入值，显式添加依赖并校验类型。
- taskSlot：当前用户请求明确表达的条件/期间/阈值 -> 已解析且验证的值。
- literal：经过契约验证的配置、字段名或结构常量；业务条件必须有适用约束，不能任意
  将一次样本的阈值当作所有未来任务的默认值。

只从调用值相等不能证明参数依赖。存在多个相同值的可能来源时，保留模型节点或拒绝编译。
禁止保存旧 tableId、rowId、evidenceId、金额结果、metrics、selectedIds 或完整旧报告作为
下次执行参数。允许同工具复用不同计算结构，且不得按任务 ID 写特例。

本地写入先覆盖已有 workspace_save_draft、workspace_export_csv、workspace_publish_report：

- 本地产物节点依赖当前观察、当前 compute 或本次模型生成内容；新工作区必须生成新产物。
- 模型撰写报告正文可以继续保留为语义边界。若当前计算输出能完整映射结构化报告字段，
  才确定性绑定 metrics/selectedIds；不缓存旧答案，不从私有验收补写业务结果。
- artifact 串行执行，维护/重放不得重新执行产物写入；为执行、重试、恢复定义幂等范围。
- 参数不能可靠泛化时留给模型，禁止把复杂写入隐藏在一个伪工具里。
- 本轮不新增付款、外部发信、平台写账或关闭工单。已有外部连接仍遵守只读范围。

在 Fast/局部图执行后，只把当前已完成输出交给模型；避免已执行 compute 被无意义重复选择。
两臂继续共用确定性工具与通用防重复/恢复保护，不能人为削弱 Baseline。

## 5. 工作区反馈修订：正常任务中的闭环

对每个训练运行执行：记录当前图和来源 -> 执行 -> 记录错误/恢复/成本 -> 更新可验证结构。
不要将工作区图标记 not_applicable 后结束学习，也不要直接退回未改变的父图冒充修复。

先实现少量有证据的 Graph Patch：

- 扩展稳定计算链：此前未被可靠编译的 compute 经过正常训练轨迹，具有验证过的参数来源、
  输入输出契约与覆盖要求后，追加到父图，使后续任务免工具选择/填参。适用证据门槛在
  实验前冻结；不得故意推迟已可编译的节点，只为产生 G1。
- 修正绑定/恢复：图节点失败后，本次模型或共享 runtime 对同一业务对象、同一子目标完成
  有效恢复且任务通过，使用公开参数/输出/错误证据修订对应节点。仅“同名工具后来成功”
  不足以认定修复，必须检查对象、条件、输出覆盖和后继依赖。
- 裁剪冗余读取/计算或合并等价节点：用契约、当前观察和真实轨迹证明等价，保留必要证据。
- 无法确定性恢复的语义子图可改为模型边界，但如其成本增加，明确记录可靠性/效率取舍。

图结构/绑定规则真实变化才建立 child，保留 parentGraphId、结构 diff、patch 类型、证据
run、适用条件和后续运行。证据计数、probation 晋升、相同结构保存不是 G1。
失败且未获有效恢复可以形成失败约束/待修诊断，不能发布未经验证的可执行替代图。

学习只读取公开任务、工具契约、工具输出、轨迹、错误和已验证恢复；私有评分可用于
通过/拒绝门控，不提供 expected metrics、selectedIds 或缺失真值给匹配、绑定和修图。
Judge 不临时接入学习器。validation/test 不生成 Patch，test 不回写任何证据。
对 test/只读产品的选择也不得修改所加载的共享版本。

零影子 rollout 不等于零 overhead。新增匹配/修订模型调用、恢复工具、本地编译/绑定/
持久化均完整计量；优先本地修订，必要反思最多一次有界请求，计入本次 Agent 成本。

## 6. 实施、测试与新 48-task 实验

1. 先完成机制与 focused 协议回归。覆盖措辞改写、条件改变、错契约、嵌套绑定歧义、
   当前数据重新计算、本地 artifact 幂等、工作区子图修订和只读加载不得改经验。
   注入协议结果明确标为测试，不作为自然进化/效率证据。
2. 只读诊断现有 V17 轨迹，找适合编译的 compute、参数来源和真实恢复类型。可用于
   设计瓶颈分析，不把旧 V17 经验注入下一次声称“空库”的实验。
3. 冻结新 runtime、工具/匹配/修订协议、模型、预算及新 experiment ID。保留 V17 原工件。
4. 小规模预检先覆盖三场景至少各两个同族 train 实例，两臂共 12 Agent 运行。验证当前
   参数绑定、反馈维护不报错、零未来经验和完整 usage；不能因成功率通过而忽略维护错误。
   有需修复的系统问题时停止扩大，修复后另建版本，保留原尝试成本。
5. 健康预检和预算条件满足后，独立空经验运行冻结的 48 train 工作包，每族四实例。
   两臂同模型/工具/通用提示/预算/恢复，Baseline 不学习，RSI 只学此前正常任务；
   run=model=read=1，任务对交替先后。不得复用不同版本旧 Baseline 来拼接结论。
6. 48-task 验收必须包括实际工作区图修订，以及至少一条可追溯的父图 -> Patch -> 子图 ->
   后续不同实例使用链。没有自然修订时必须报告本项未达标，不能人为注入错误、建立
   相同结构的新版本或反复重跑直到出现；G2 未发生不强求，但不宣称多代进化。
7. 全量列 token、模型/provider 请求、工具/拒绝/错误、最终成功率、恢复、P50/P95/最大
   延迟，分冷启动/完整图复用/局部图复用/修订。学习来源成本不得漏计。
   Judge 预算另列，不自动扩大裁判矩阵；模型服务异常时保留未知 usage 并停止付费扩跑。

本规格不解除已有模型预算暂停约束，不在讨论 session 发起付费运行。执行 session
先检查现有预算授权及在途任务；不足时继续完成代码、协议测试和保存轨迹展示。

## 7. 可展示交付

- 产品：自然语言 + 用户附件 -> 已审核候选图 -> 当前参数 -> 真实读取/计算/本地成果。
  普通工作区不学习也可以只读复用，拒绝理由可在技术详情查看。
- 实验：每族按第 1/2/3/4 次任务展示当前图、来源、实际 Patch、同任务两臂质量/token/
  请求/恢复和累计节省；明确第几次任务生成图，第几次开始执行子图。
- 回放区分 model/read/compute/artifact/control，图 diff 不仅显示版本号。
- 展示已确定工具的选择/参数绑定确实无模型请求，但净收益用成对实际用量；不生成
  人造增长或瓶颈曲线，不将一次修改/G0 复用叫连续递归进化。
- 最终交付 live URL、三场景真实输入/报告、图来源/修订/后续使用、全量成本与可靠性账本，
  并更新状态/设计/TODO/实验记录和 Git 提交。
