# 三分钟录制脚本

入口：`http://127.0.0.1:5173/#analysis`。默认选择候选 `finance-attribution-v5-repair-probe`；页面上的运行过程均为保存轨迹回放，不制作假实时动画。

**0:00–0:25｜业务任务。** 打开“数字员工”，展示简洁财务请求与当前附件。说明数据来自 Olist 公开历史记录，Agent 只看到业务目标、口径和交付要求；私有评分答案不进入提示、匹配或工具。

**0:25–0:50｜对照设计。** 进入“数据分析”，指出状态为 candidate、实验 ID、runtime、资产和协议。A 是“图执行 · 不学习”，每次重新规划和编译；B 是“图执行 · 在线RSI”，从独立空经验开始。两臂共享27B模型、提示、工具、恢复、预算和输入。

**0:50–1:20｜创建成本。** 点击 FX01，展示两臂业务报告均通过。在线臂创建 G0/M0，但使用151,265 token，高于不学习臂103,558。明确冷启动更贵，创建经验本身不是收益。

**1:20–1:50｜复用与覆盖扩展。** 点击 FX09。在线臂实际执行 G0 的13个节点，并从当前成功轨迹补充支付记录计数、订单状态与月份不同值统计，形成G1/M1。展开父子diff；说明这是覆盖扩展，不是错误纠正；同时指出运行后审计发现一个错误的 `payment_count` 金额求和节点，最终正确值由其他当前观察和模型完成，因此保持候选。

**1:50–2:15｜修订后使用。** 点击 FX10，查看其实际使用 G1/M1 的18个节点、当前附件重算结果、3次模型请求和0工具错误。只有这一步完成后，才把前一步称为有后续使用的修订证据。

**2:15–2:40｜收益来自哪里。** 展示请求分解：读取选择11→1，计算选择28→16，混合决策1→0，报告组合3→3。解释Graph RSI省掉的是重复工具选择与参数绑定决策，当前报告仍由模型生成。再展示绝对总量609,447→324,130 token、47→23请求、369.756→184.904秒；候选页不把百分比包装成formal收益。

**2:40–3:00｜可靠性和限制。** 展示两臂3/3、usage完整、实际图使用2/3，以及失败审计入口。说明早先runtime变化停止和恢复工具屏蔽失败都原样保留，不进入当前指标。本实验只有三个财务实例，没有客服/技术工单、独立Judge或人工全文复核，因此结论限定为一条可审计的创建、复用、覆盖扩展和后续使用机制链。
