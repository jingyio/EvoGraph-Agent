# 轨迹重构录制脚本

入口：`http://127.0.0.1:5173/#home`、`/#trajectory`。
仅使用当前保存run的成果、轨迹和计量；没有真实G/M修订时不画进化动画。

1. 在工作台选财务，拖入 `test/轨迹复核-v1/财务/输入附件.json`，粘贴同目录问题。
   展示12订单、一对多支付/商品及明确的5分/8期/缺失规则。准备任务不发起模型。
   若展示实时运行，费用确认后仅启动一次；保存轨迹回放不能称实时推理。
2. 进入轨迹重构预检，选保存实验，先点击“财务多原因复核1”的实际报告。
   展示分原因数量、重叠清单、空组、缺失待核查和来源；下载链接关联同一run。
   切Baseline时解释报告结构相同，失败状态原样保留。
3. 点击财务第二实例，打开“轨迹来源 · 当前槽 · G/M真实差异”。核查匹配quote及
   实际compute参数10分/12期，不把历史别名中残留的数字当作本次比较阈值。
4. 只在真实后继版本及后续使用存在时展示G/M差异。G0是初次编译；相同图支持增长
   不是进化。独立schema适用修订M与图结构G分别查看，不把协议注入测试当业务实证。
5. 查看同组单次token/latency和全局累计曲线，点数据点回到同一输入/run/报告。
   曲线不补点、不平滑，费用含匹配和恢复。未完成pair尚未结算，质量失败仅诊断。
6. 客服、技术工单按相同路径展示各自已运行成果；未启动项直接说明未运行，不切到
   旧V17报告假装本轮通过。输入材料目录已备齐，CFPB摘录和GitHub来源边界须保留。

当前完整output依赖推导与本地产物图执行尚未交付；正文和报告参数仍由本次模型提交。
已审核读取/compute结构可经 `python -m scripts.review_trajectory_experience --experiment
<id> --graph <id> --install` 注册到产品只读经验库。该命令验证来源收据及可重建结构，
不运行模型，不改变实验经验，不表示独立质量裁判。服务空闲重新载入后生效。
