# 已确认的设计决策

## 2026-09-14：细粒度共享工具与模型边界

两臂使用相同的通用物理计算接口，以真实成功轨迹的工具/参数数据流学习可复用子图。单次完整对账接口过粗会限制可跳过决策；不能仅拆 IR 后宣称增加了实际收益。独立调用允许批量，禁止人为增加不学习臂请求。单位转换可留给当前模型，其他兼容依赖仍可复用。每个 run 的收据只在 ToolContext 存在，跨任务保存的是依赖而非答案。

历史 TIG 惯性执行不自动恢复；当前借鉴 AutoTool 的历史工具结构/参数关联思想，以当前业务覆盖校验约束子图执行，不声称完整复现或优于 AutoTool。新归因实验与旧 Plan+ReAct 指标完全隔离。真实开销与失败均计入，初始创建、经验复用和反馈修订分别报告。详见 [设计说明](granular-autotool-design-2026-09-14.md)。

## 2026-09-14 D58：reconciliation clause IR 与单次物理调用

| ID | 决策 | 理由与实施边界 |

| D58 | reconciliation 以 clause IR 选择、以单次物理调用执行 | 成功的 `workspace_reconcile_keyed_sums` 收据按 aggregate、derivedTotal、逐条 comparison 和 missingByAlias obligation 编译；后者只能引用已选 aggregate，comparison/derived 必须满足依赖闭包。当前请求槽重绑、alias/core/Schema 校验完成后，同一 bundle 降为一次真实工具调用。任一 clause 无法证明来源时只拒绝该 clause；V2 的 `missing equals 0` 不作为缺失语义，缺失只来自工具的 `missingByAlias`。这是通用工具协议层修复，不写入财务题族、固定阈值或私有答案；旧工件不改写，真实成本收益待新 smoke。 |

## 2026-09-14 D54：V3-r3 以最小可审计口径修复财务复核

| 决策 | 内容 | 原因 |
|---|---|---|
| D54 | 新建 V3-r3，不改写 V3-r2；财务题面只增加一条订单主体、一对多与分/BRL口径。字段类型/单位与缺失原则进入通用系统提示；文本键、数值聚合、比较数组和原始单位阈值进入对账工具契约；模型上下文只去除字节完全相同的重复行观察，完整 ledger/trace 保留。 | F01 的失败来自文本 ID 被作为聚合字段、比较参数格式错误、分/BRL混用和重复观察回灌。把业务口径完全藏进系统提示会使候选任务不可审计；把它拆成步骤又会形成 SOP。V3-r3 只增加业务人员可读的一句定义，其他修复是跨场景运行时规则。新的空 RSI 经验库预检必须使用 V3-r3；在用户再次审阅前不发起新的付费调用。 |


## 2026-09-14 D53：V3-r2 的自然题面与真实 Fast 门槛

| ID | 决策 | 理由与实施边界 |
|---|---|---|
| D53 | 新建 V3-r2；用户题面与机器交付契约分离，Fast 复用率以 50% 为候选硬门槛 | V3-r1 的题面仍把统计键、原因组和 ID 字段交给 Agent，形成 benchmark/SOP 味并污染可学习语义。V3-r2 保留同一公开记录选择，但题面仅保留业务目标、口径、阈值、缺失含义、成果和禁止动作；动态报告工具 Schema 承载机器格式，`deliveryContract` 不进入模型消息或轨迹匹配。48 个任务组织为六个连续 cohort，每组 8 项，创造合法冷启动后复用机会；只有保存 RSI run 的实际 `planningPath=fast` 达到 50% 及以上才可通过发布门槛，不能把机会、G0 创建或 partial 当作 Fast。 |


## 2026-09-14 D46–D48：V3-r1 失败驱动修订

| ID | 决策 | 理由与实施边界 |

## 明确没有确认成结论的说法

- Graph 一定比强 ReAct 少工具、低延迟或零错误。
- 30 个任务的系统收益都来自 Motif 学习或递归进化。
- 多次自然成功就可以把图推广到整个场景。
- 模型评分 0.94 等于 94% 成功概率，或同模型 Judge 已提供独立质量证明。
- 所有自然语言规划均可在本地零成本反思成正确修复。
- 模型昵称、粘贴建议里的角色划分或 `.save_state` 是本项目已实现的自动能力。

## 更新方式

讨论形成新决策时，增加/修订带 ID 的条目，并注明日期和状态（已确认、提案、被替代）。重大替代保留原因，不静默重写历史实验。执行 session 可自行完成已授权范围内的常规实现选择；不要把文档维护变成每次修改都要确认的审批流程。

新方案尚未落实时写进 TODO 的“待设计”区域，不能直接改写 ARCHITECTURE 为已实现。

当前 Release Manifest 可以绑定到一个已停止的 candidate 运行，但只能显示同一运行的失败回放、原始开销和审计入口。质量门槛未通过时，前端不显示节省率或累计收益曲线，也不由历史实验补数；Fast、G/M 和质量结论均明确为未获得证据。

## 2026-09-14 · 成本使用固定价格快照而非估算调用数

数据分析页的美元成本是可复算的 **模型 token 成本估算**：保存运行的实际输入/输出 token × 清单中固定的 OpenRouter 价格快照。不能用 LLM 请求数、总 token、当前环境模型或未来价格反推历史成本。清单同时保留 27B 和 9B 默认模型单价，运行只使用自身保存的 `models`；未知 usage、模型或混合角色的 phase 计量不闭合时成本为未知。候选或质量不完整测试组仍显示已知绝对成本，但不生成成本节省结论。
