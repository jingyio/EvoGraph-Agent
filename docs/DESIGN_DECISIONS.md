# 已确认的设计决策

日期：2026-09-10。下列是用户讨论中已确认并指导当前实现的约束；实现的实际覆盖范围以 ARCHITECTURE 与代码为准。

| ID | 决策 | 理由与实施边界 |
|---|---|---|
| D01 | 做岗位型数字员工，不做完整 Agent 平台 | 工作直接服务质量、效率、进化和可靠性证据 |
| D02 | Python 后端，React/TS 前端；HTTP 统一在 model_client | 业务状态由 runtime/context 管理，provider 不拥有生命周期；关闭 thinking |
| D03 | 工具文档简短，参数明确，按任务/显式 intent 匹配 | 不索取隐藏 thought；BM25 是当前本地实现，不是完整论文复现 |
| D04 | Plan 与执行角色分开配置，允许大小模型协同 | 同模型时如实标记；没有压测不宣称高并发收益 |
| D05 | 复用结构与 Plan，不缓存旧业务结果 | 当前 ID、字段、分页来自本次观察；契约和范围检查不能省略 |
| D06 | 图进化利用正常任务，不额外进行候选影子 rollout | 不做无必要的多候选搜索；有明确适用边界时采用单个带恢复的 Patch |
| D07 | 失败先恢复当前任务，再根据有效证据生成后继图 | 临时交接模型不等于永久退回父图；未知错误保留待分析 |
| D08 | 版本增长必须对应结构变化 | 证据积累、适用门槛满足、重复保存 G0 都不是新一代进化 |
| D09 | 不独立开发庞大的 typed IR | 文档约定落实到现有 runtime、schema、prompt；未支持的节点不得只画图宣称实现 |
| D10 | 使用来源清晰的数据，禁止静默回退沙箱 | 真实平台、项目种子记录、公开真实历史数据必须区分 |
| D11 | train 学习，validation 选型/验证，test 冻结评估 | 验证失败可用于分析瓶颈，不能直接提炼进经验；新的修改需正常训练证据 |
| D12 | 强基线与 RSI 共享通用执行提示 | 观察复用、防重复和独立批量调用对双方开放；Plan 基线也要比较 |
| D13 | 固定任务和图版本，保留失败、冷启动与恢复成本 | 成功子集可另列，但不能替代全部尝试成本；裁判成本独立 |
| D14 | LLM Judge 和事实校验并行存在 | 三维 0–10，reward 权重 50/30/20，双顺序匿名；分歧不重试到满意，格式最多修正一次/顺序 |
| D16 | 删除旧合成业务沙箱 | 用户于本次交接明确要求；移除代码、数据、专用接口和页面，保留真实平台与当前任务库 |
| D17 | 局部子图以受约束的语义筛选接口复用 | 2026-09-10 已确认。Plan 角色只能声明可由上游列表已声明字段验证的精确相等条件；编译器负责绑定和本地筛选。无法可靠确定时交给模型，字段/类型变化失败关闭；不新增大型 IR，也不硬编码任务答案。 |
| D18 | G-Agent 式三路径只复用可执行结构，不照搬参考实现的专用策略 | 2026-09-10 已确认。Graph RSI 先 Fast 完整 Workflow，再用 composition 角色的粗子目标检索/确定性组合 Persistent TinyEdge，覆盖不足才调用完整 Plan。TinyEdge 只由通过评分的 train 图连续读取链产生，记录 support/来源/依赖/槽位；执行器直接消费已选 ID。当前不做论文 embedding、gap filler、LRU、AppWorld codegen 或 §4.6 Transient TinyEdge Group，普通工具并发不能计为组批收益。 |
| D19 | AutoTool/TIG 惯性执行已退役 | 2026-09-10 后续决定：保留 BM25、参数契约、序列化和历史轨迹可读性，但移除活动的惯性预测执行和学习更新；不再以触发率或门槛调优追逐收益。旧负向实验保留，不能作为现行机制收益。 |
| D20 | 修复后对照复用已审计 RSI-only，并补跑无学习 Baseline | `online-rsi-graph-precheck-v3` 的 36 条 RSI 在相同 frozen manifest、模型名、预算、工具契约和源码 runtime revision 下被复用；新目录只串行运行 `plan_react`。比较明确标注为分时匹配，Judge 独立计费；provider endpoint 的历史指纹未保留，不能事后宣称完全可重建的同端点试验。详情见 `online-rsi-matched-results-2026-09-10.md`。 |
| D21 | 维护与报告恢复错误优先按正确性修复，不包装成研究收益 | 2026-09-10 已确认。TinyEdge 挖掘按 `(scenario, contractHash)` 隔离，分区失败不阻断 Workflow/图保存；BM25 仅排序，图编译必须验证能力和任务语义。报告评分失败至多一次针对性重提，证据格式修复不允许重读。该共享恢复行为也作用于基线，因此旧对照在此故障面上不与修复后运行混合。 |
| D22 | 编译器可拒绝与任务语义不兼容或等价的读取节点，但不得静默改写父图 | 2026-09-10 已确认。意图/输出契约过滤错工具，任务语义裁剪独立无关读取，结构等价节点合并；旧图标记 `needs-repair`，通过的正常 train 重编译才保存可审计子图。它是正确性/效率修复，不作为自主 G1/G2 进化。 |
| D23 | 最终在线结论使用独立空经验的严格串行 V4 工件 | 2026-09-11 已执行。固定 36 条不同 train 任务，`run_limit=model_limit=read_limit=1`，两臂同模型、提示、预算、工具和有界恢复；RSI 只在本流正常任务后更新经验，Judge 在 Agent 后单列。历史分时、负向和补充规模工件保留，但不得与 V4 严格全量结果拼接。 |
| D24 | 交付展示以只读 artifact 派生数据为准，结构化通过与报告审计分开 | 2026-09-11 已确认。主页面展示 36 个保存的同任务对、真实 DAG/绑定/工具轨迹和 Agent 计量；`gold.json` 只在后端导出审计布尔结果，绝不提供给 Agent、Judge 或浏览器。严格摘要审计覆盖 schema、精确结构化字段、当前观察证据、已知 ID/数字与金额单位；它不是全面 NLP 事实判断，因此不得用其替代独立 Judge 或人工复核。 |
| D25 | 展示按三大业务领域聚合，动态回放只消费保存 trace | 2026-09-11 已确认。完整 36-task 固定 manifest 仍是主分母，财务/客服/技术工单各展示 12 对；技术 `unassigned` 因收益较小不作为代表回放，但不能从总量或领域聚合中删除。同步播放器显示三条真实保存轨迹的累计 LLM、token、工具和时间步，不生成假事件或假性能。公开历史数据与本地 JSON Schema 只读工具必须显式标注为工作流模拟边界，不得写成生产企业部署。 |
| D15 | 将当前讨论 session 与用户将建立的执行 session 分工 | 文档承接设计和状态，不依赖聊天长上下文；不绑定具体型号的能力假设 |

## 明确没有确认成结论的说法

- Graph 一定比强 ReAct 少工具、低延迟或零错误。
- 30 个任务的系统收益都来自 Motif 学习或递归进化。
- 多次自然成功就可以把图推广到整个场景。
- 模型评分 0.94 等于 94% 成功概率，或同模型 Judge 已提供独立质量证明。
- 所有自然语言规划均可在本地零成本反思成正确修复。
- 模型昵称、粘贴建议里的角色划分或 `.save_state` 是本项目已实现的自动能力。

## 更新方式

讨论形成新决策时，增加/修订带 ID 的条目，并注明日期和状态（已确认、提案、被替代）。重大替代保留原因，不静默重写历史实验。执行 session 可自行完成已授权范围内的常规实现选择；不要把文档维护变成每次修改都要确认的审批流程。
