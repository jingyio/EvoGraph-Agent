# RSI 最终串行在线实验协议

日期：2026-09-11。该协议在结果产生前冻结，服务于最终交付，不替换或改写历史 `online-e2e-train-v1`、分时匹配结果或并发补充工件。

## 目的

以同一组 36 个正常 train 任务比较强 `Plan + ReAct` 与 `Graph RSI`，验证在线经验是否在后续同族任务被实际使用，并记录包含冷启动、规划、恢复与在线维护请求的 Agent token。主目标为：

```text
1 - RSI 全部 36 个任务 token / Baseline 对应 36 个任务 token
```

约 30% 是验收目标，不是调参或筛选结果的许可。Judge token 单列，不进入该式。

## 冻结对象与串行边界

- manifest：`finance/cancelled_payments`、`finance/installments`、`support/channels`、`support/timeliness`、`tickets/unassigned`、`tickets/labels` 各六个不同 train 实例，按六轮交错到达。
- 两臂都遵循相同 manifest；每臂内部看到的任务顺序相同。每个任务可交替 Baseline/RSI 先后，以缓和分时供应商负载。
- `run_limit=1`、`model_limit=1`、`read_limit=1`。不运行本轮的并发 1/2/4 矩阵，也不把历史并发工件计入主结论。
- Baseline 使用匹配强 `Plan + ReAct`、无跨任务学习；RSI 使用 `graph_rsi`，AutoTool 惯性分支保持关闭，从新的空经验库开始，只在一个 train 任务完成后再向下一任务暴露经验。
- 模型、提示、工具、预算、恢复和确定性评分保持一致。共享报告证据规范化在两臂均启用：只有所有任务记录已被本次真实观察时，runtime 才规范化 `evidenceIds`；它不会注入未观察证据或更改业务字段。

## 分阶段执行

1. 先用独立工件重跑两个既有长尾任务以及 10/30/60 条真实 train 记录规模点，验证共享证据修复、空/非空补查和 60 条范围的报告覆盖；这些诊断不会污染主实验经验库。
2. 启动 36 条正式流的前两轮（12 条），只运行 Agent，不启动 Judge。无未解释维护错误、无无界报告恢复、且有后续实际 Workflow 使用时，原记录直接计入正式流。
3. 不改代码、模型、提示、预算或学习规则时续跑余下 24 条；所有 72 个 Agent 运行结束后，再对 36 对报告作匿名 A/B 与 B/A Judge。
4. 若协议相关实现变动，旧预检标为独立版本，重新建立新的空经验库；不拼接不同版本。

## 预计调用量与停止规则

- 根据最近匹配运行，预计约 301 次 Agent 模型请求（Baseline 197、RSI 104）；这是历史估计，不是预算或承诺。硬上限为 72 × 24 = 1,728 次执行/规划请求。
- Judge 正常为每对两个请求，即 72 次；每方向最多一次格式修正，硬上限为 144 次。Judge 费用独立记录。
- 基线或 RSI 业务失败均保留在分母。系统性模型/网络/计量故障会暂停后续任务并保存 checkpoint；不无限重试、不降阈值制造命中。

## 可比性与展示

新串行结果是主 token 对照。历史 `online-rsi-graph-matched-v4` 因共享报告行为在故障面变化，只作为历史参照，不与修复后结果拼成严格全量结论。页面必须显示经验形成与实际使用、同任务成本差、冷启动累计、失败与负收益；没有 G1/G2 或 Composition 命中时明确标为未观察到。
