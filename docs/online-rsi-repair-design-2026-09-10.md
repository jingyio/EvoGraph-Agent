# 在线 RSI 机制与恢复修复设计

日期：2026-09-10。此文针对隔离旧实验 `online-e2e-train-v1` 的只读审计；旧运行记录不修改。

## 已验证根因

1. `record_workflow` 将所有场景的 Workflow 传给只含当前场景工具的 TinyEdge 挖掘器。外场景工具被误判为非读取工具，25 次维护异常还阻断了后续完整 Workflow 图保存。
2. 图选择把 BM25 排名当作能力证明：根节点可选 scope，详情节点可在无兼容候选时回退到不产出所需字段的 record 工具。Plan 还能把任务中的包含式数值条件改写成精确相等。
3. 报告修复轮次只在模型没有工具调用时计数；连续失败的 `publish_report` 不受该上限约束。
4. `motif_first` 的惯性入口仅在 `graphHandoff` 时运行。旧实验没有 handoff，因此 0 次尝试是入口不适用，不是阈值拒绝。

## 最小修复

- Workflow/TinyEdge 按 `(scenario, contractHash)` 分区挖掘。当前分区成功时原子替换该分区，其他分区保留；失败记录 `unknown_tool`、`non_read_tool` 或 `contract_mismatch`，但不会中断 Workflow/完整图保存。
- 本地选择仍以 BM25 排序，但必须通过列表/详情结构角色与输出语义能力检查；不兼容时编译失败并回到原模型。任务文本是条件权威，明确把包含式数值条件缩窄为精确相等的 Plan 被拒绝。
- 每个任务最多一次针对已观察评分失败的再提交；相同失败签名或第二次失败终止为 `limited`。仅证据格式失败时只开放报告工具并反馈当前观察到的 evidence refs；事实失败不披露 gold，也不静默修改结论。
- 每次模型决策前记录 AutoTool 入口状态及不尝试原因。保留 `motif_first + graphHandoff + 非 fallback + 一次` 的安全门，不实现 `autotool_first` 或调低阈值。

这些是正确性和恢复修复，不计为 RSI 研究机制收益。共享报告恢复逻辑同时影响基线，因此旧在线对照在该故障面上不再与修复后运行兼容。

## 验收

注入回归覆盖跨场景交错分区、能力/语义拒绝、报告失败有界恢复和 AutoTool 入口日志。通过后才建立新的隔离小规模 train 预检；它不得与旧实验的经验或结果拼接。
