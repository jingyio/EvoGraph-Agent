# 细粒度工具与历史子图复用

本轮目标是隔离跨任务学习的贡献。两臂均是图执行 Agent，使用相同模型、提示、工具、冷启动规划/编译、恢复和预算；不学习臂每次冷启动，在线臂从独立空经验学习此前成功 train 轨迹。

## 为什么拆分

旧 `workspace_reconcile_keyed_sums` 是完整确定性对账操作，可能使冷启动路径只需规划、对账决策和报告三次模型请求。历史图匹配也消耗一次模型请求，可跳过的真实决策太少。仅在编译 IR 内拆片段不能改变这个物理接口限制。

`granular-compute-v1` 提供字段映射、按键聚合、主表关联、派生数值、单条件比较和缺失选择六类通用操作。调用者自主决定工具、字段、别名和依赖；独立操作允许批量调用，依赖操作必须引用实际已执行的上游收据。不人为提高对照臂的模型次数。新接口仅候选归因任务启用，原上传工作区继续兼容。

## 收据和参数来源

收据存储在单 run 的 ToolContext 中，以当前随机 receiptId 引用。图编译保存实际工具输出的 `$output` 依赖，不保存旧业务值或收据。回放重新读取当前表、计算并生成新收据。子表一对多先聚合再以显式主表对齐，缺关联为 null；数值缺失、非有限值和别名冲突失败关闭。

实际阈值不能在当前请求中逐字证明时，对应比较节点保留模型边界。例如 `0.05 BRL` 的 5 分转换由当前模型决定；其他兼容映射、聚合、关联和缺失节点仍可复用。当前请求直接写明的分期数可以绑定为当前槽。匹配器不能把报告/摘要视为需要重新规划的未覆盖业务操作。

## 与 AutoTool 的关系

当前活动代码保留本地 BM25 工具检索；它不等同于完整 AutoTool。旧 TIG 惯性执行已退役。历史下一工具转移本身无法证明当前业务义务和条件兼容；本轮使用当前约束校验的子图及实际参数数据流，借鉴历史结构替代重复工具选择/填参的思想，不宣称复现完整 TIG 算法，也不宣称优于论文。

两臂共享工具检索，因此检索或新物理工具本身的收益不能归因于在线 RSI。只有后续实际执行历史版本所减少的请求/成本才有归因依据。调用粒度增加也可能提高冷启动成本；必须计入首任务、匹配、学习、恢复、持久化和全部失败的净 token/时长。

## 实验冻结

因另一在途任务在同一工作树修改数据分析 API，本轮真实预检从 `artifacts/granular-runtime-v4/backend` 源码快照导入，运行前冻结逐文件 hash；配置链接原 `.env`，进程覆盖统一 27B，thinking 关闭。运行记录仍位于标准 `artifacts/attribution-experiments/<id>`，快照不包含凭据。不修改旧 V1/V2/V3 的任务或实验工件。
