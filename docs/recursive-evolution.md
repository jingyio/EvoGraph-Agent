# 递归进化实验

Python `backend/evolution.py` 承担执行、学习、验证、晋升及持久化；React `src/EvolutionPanel.tsx` 展示轮次、父子关系和成本。通过 `/api/evolutions` 交换 JSON。

开发环境分别启动 `npm run dev:backend`（4317）和 `npm run dev:frontend`（5173）。Vite 代理 `/api` 到后端，模型凭据仍只保留在后端 `.env`。生产构建也可由 FastAPI 提供。

## 业务真实性

现有配对评测和新增进化实验使用合成 JSON 沙箱，模拟回款核对、工单分派、容量和 SLA，并非真实企业记录。ERPNext、Zammad 已部署，连接器仅做平台只读访问。现有客服 Agent 已承担工单处理，无需第三个 GitHub 项目；真实工单环境优先沿用 Zammad。

## 递归闭环

ReAct 冷启动产生真实模型轨迹，编译并影子验证候选读取图。在另一份快照上分别运行父版本和候选版本；两者完整业务状态校验通过、用量完整、候选模型请求严格减少、总 token 和工具错误不增加时，才暂定晋升。下一轮由晋升后的图产生新轨迹，再编译候选，形成执行结构的递归更新。

首次训练 base、验证 changed；后续训练 changed、验证 exception。快照重复使用，属于开发验证集，不是独立测试集。每轮仅一次配对，晋升不代表统计显著提升；报告语义未评分，不能声称完整质量提升。

每次任务使用独立状态副本。最多五轮，每轮最多三次任务，每次沿用模型、工具与超时预算。总成本包括训练和验证模型调用；影子读取单独显示。用量缺失禁止晋升。取消、进程中断和失败保留证据。

候选图保存在 `artifacts/evolutions/<experiment-id>/candidates/`，实验记录保存在 `artifacts/evolutions/<experiment-id>.json`。候选和晋升图均不自动进入公共经验库，`activeGraph` 是实验内部版本。结构相同停止并标记停滞，不合格候选停止并保留父版本。图记录父 ID 和来源事件，原始运行进入普通历史。

## 适用范围

这是读取图层面的递归经验更新，没有训练基础模型或修改优化器算法。当前编译器仅提取首次写入前、参数可安全绑定的读取结构。无法绑定自然语言查询时停止扩展，因此可能第一代后就停滞；界面不会把复制相同图称为进化。

更强的递归改进需要条件节点、反馈驱动的候选生成、独立报告事实评分以及规则工作流基线。批量工具调用和相同业务校验始终对 ReAct 开放。

## 首次真实验证

实验 `c6c20286-a035-4862-989d-b54244a0bf0e` 使用 qwen/qwen3.5-27b、关闭 thinking、允许批量工具调用。冷启动训练 7 次 LLM，changed 验证父版本 7 次、候选版本 13 次；双方完整财务状态通过，但候选工具错误从 0 增至 1，因此第一轮拒绝晋升，没有进入第二轮。总训练与验证消耗 27 次 LLM、161,354 token，额外影子读取 9 次。这是真实负向样本；递归父子链和停滞逻辑另由注入测试提供程序验证，不能将测试程序结果作为真实模型进化成果。
