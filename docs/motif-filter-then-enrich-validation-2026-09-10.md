## 最小设计

Motif 不新建 IR。Plan 的详情步骤可带一个语义选择接口：

```json
{
  "selection": {
    "kind": "match",
    "sourceStepId": "list_orders",
    "field": "status",
    "operator": "equals",
    "value": "canceled"
  }
}
```

- 输入：同一 Plan 内已依赖的分页列表步骤、该列表工具声明的字段、一个原始类型字面量。
- 输出：现有详情读取节点的 `foreach.filter`；列表观察本身不被改写，详情工具只接收命中记录的当前 ID。
- 适用：详情步骤是单 ID 读取，筛选字段在上游列表工具契约中声明，且规划模型能从当前任务可靠给出精确相等条件。
- 绑定：编译器校验来源步骤是依赖、字段是声明输出，并使用既有 `item.id` 绑定详情参数；不保存旧记录 ID 或任务答案。
- 语义调用位置：仅 Plan 角色产生 `selection`；图选择、筛选和执行均为本地确定性行为。
- 不确定路径：Plan 可返回 `{ "kind": "model", "reason": "..." }`，编译器将该详情子图标为 `defer`。若当前列表缺字段或字段类型变化，图失败但保留已完成上游观察，由本任务模型恢复；没有硬编码业务答案。
- 复用与补查：条件字段直接复用本次列表字段；现有 `reuse.onMissing=detail` 仍只对入选记录缺失的详情字段逐条补查。补查、模型恢复、错误、token 与延迟都保留在任务账本中。

## 同 Plan 执行对照

`7c32fa3e` 在与热启动相同的训练任务上使用 `plan_react_reuse`：复用同一份保存 Plan，但所有读取和报告仍由 ReAct 决定。它结构化评分通过，使用 7 次 LLM、6 次工具、22,135 token、24.88 s。相对该次 ReAct，编译 Motif 运行少 4 次 LLM、少 11,765 token、少 2 次总工具调用，但总延迟高 1.16 s。

该 ReAct 也自行只读取了入选订单，所以这不是“避免 9 次详情读取”的同任务反事实。已验证的事实是 Motif 在两个自然训练运行中实际排除了 9 条记录并只发出 1 次详情调用；冻结配对评测尚未运行，不能据此声称总体 token 或延迟优势。
