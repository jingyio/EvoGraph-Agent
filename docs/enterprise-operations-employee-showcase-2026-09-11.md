# 企业运营数字员工主工作台

日期：2026-09-11。该文档定义展示层，不新增实验、模型请求、任务或学习数据。严格实验的唯一主证据仍是 `online-rsi-serial-final-v4`。

## 目的

将已有的结构化业务分析 Agent 以一个企业运营员工呈现，同时保持实验口径可审计：

- 证据层：固定 36 条 `train` 任务、严格串行 Baseline/RSI 对照、原始轨迹、结构化验收和受限 Judge。
- 产品层：主页展示一个企业运营数字员工；财务分析、客服分析和研发运营是其可切换能力，而不是三个独立产品。主页从业务需求、工作过程和业务简报开始；36 个案例、原始 ID、成本曲线和审计细节留在专门入口。

产品层不改变运行、不会从 `gold.json` 生成报告内容，也不把岗位名称写回经验库。

## 能力映射

| 员工能力 | 保存任务领域 | 业务产物 | 展示样本 |
|---|---|---|---|
| 财务运营助手 | Olist 订单、支付、分期 | 订单异常与支付风险简报 | `finance-cancelled_payments-02` |
| 客服运营分析师 | CFPB 投诉 | 投诉渠道与响应健康简报 | `support-channels-02` |
| 技术研发管理助手 | Zammad GitHub Issues | Issue 健康与待办简报 | `tickets-labels-02` |

主页选择一个业务能力后，加载对应的已保存工作记录：用户可见的是业务需求、运行时步骤、模型/结构化执行差别、提交的关键指标与完整简报入口。`#compare` 和 `#insights` 保留全量 36 项的成本、质量和审计数据；它们不是员工接单的第一视觉层。

## 可主张与边界

- 可以主张：V4 的 36 对严格串行任务中，RSI 达到 36/36 结构化通过、token `-35.6%`、模型请求 `-43.8%`；6 个 G0 中的 24 次后续 Fast 复用实际完成。
- 不可以主张：已经完成生产 ERP/CRM/工单写入部署、生成了 PPTX、观察到 G1/G2 结构修订、Composition 实际收益、独立 Judge 质量优势或稳定的 provider 延迟优势。
- 数据边界：任务使用公开历史数据，经过按任务范围隔离的本地 SQLite + JSON Schema 只读工具暴露。岗位叙事说明业务形态，不能替代真实企业系统接入证明。
- 报告边界：`/report` 是依据本次 Agent 已提交 facts 和本次实际观察证据渲染的 HTML，可打印但不是自动生成的 PowerPoint。

## 录制入口

- `/#home`：企业运营数字员工主工作台、业务能力切换、真实工作记录回放和业务简报。
- `/#compare`：36 条全部固定任务的 Baseline/RSI 串行对比与三领域保存事件回放。
- `/#replay?task=finance-cancelled_payments-02`：模型决策与结构化执行、DAG 依赖和当前参数绑定的逐步对照。
- `/#insights`：严格实验、审计、恢复和局限。

旧 `/#employees` 链接会重定向至 `/#home`，避免产生第二个“岗位页”。

建议录制顺序：主页中选择财务分析并播放工作记录、打开实际简报 → 进入该任务回放核对模型/图执行差异 → 回到对比页展示全量 36 对累计成本 → 在 RSI 效果页说明 Fast 复用证据和未证明事项。
