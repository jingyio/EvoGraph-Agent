# 导师目标与项目验收

项目目标是在可展示的数字员工任务中证明：相同或更好的工作质量、更低 token/cost/latency，以及由真实反馈推动的流程改进。前端动画、图版本数量和成功工具调用不能单独代替这些证据。

| 目标 | 本轮实现 | 验收证据 | 暂不宣称 |
|---|---|---|---|
| 相同效果、更低开销 | Strong ReAct 与 Graph RSI 冻结成对评测 | 同任务、同模型、共同提示、全部尝试的 token 与延迟 | 未配置价格时的美元成本；仅成功子集的总体收益 |
| 质量与可展示成果 | 所有策略共用 HTML 报告模板与工具证据表 | 结构化评分、实际读取证据、独立人工文字复核 | 尚未复核的报告文字质量相同 |
| 递归进化 | 正常训练任务生成/修订图，验证集与测试集分离 | 来源轨迹、父图、Patch、后续运行实际使用 | 没有真实结构修改时的多代进化 |
| 流程可靠性 | 每对保留错误、预算耗尽、图回退和失败结果 | 全部结果的成功率、错误率、重复评测记录 | 单次零错误等于长期零错误 |

## 工作选择原则

每次增加能力前，明确它服务于哪个目标、需要什么证据，以及新增的运行开销。优先完成会改变结论的实验和业务结果展示，不扩展成 Agent 平台。性能测试前固定任务、提示、图与工具契约，性能测试中不针对结果修复同一批运行或重试到成功。

生产执行与科研评测的成本分开：在线图维护不额外 rollout；成对评测为了对照运行两种策略，属于显式实验工作。冷启动 Plan 和恢复成本计入本次运行；历史训练成本单列，来源不完整时不伪造完整学习总成本。
