# Plan、AutoTool 自动图与并发执行

工具文档只补用途和主要返回字段，见 [简明目录](tool-catalog.md)；精确参数保留 JSON Schema，不新增冗长的输入来源、前置条件或错误说明。

## 流程与分工

1. `backend/gagent.py:build_data_plan` 调用规划角色，生成当前任务的数据获取子目标和依赖。每个子目标是显式 intent，不读取或要求模型内部思维链。
2. `backend/autotool.py:retrieve_tools` 用当前 intent 检索短工具描述，采用本地 BM25、英文词和中文二元组，召回 top-4。它是词汇检索，不是嵌入语义匹配，也不保证召回率。
3. 执行模型从每个子目标的候选中选工具；只输出节点 ID 和工具名。
4. `backend/intent_graph.py` 按工具签名与依赖自动绑定分页及 `records[].id`，生成 foreach 节点，NetworkX 检查 DAG。拒绝无上游列表、多个不明确列表、未知工具、越出候选和写入工具。编译器只支持当前任务库的无参、分页和单记录 ID 读取契约。
5. 依赖满足后的读取节点及遍历调用并发执行，模型使用本次观察计算并发布报告。整个图的调用记录以批次注入模型上下文，不为每次读取伪造一轮单步 thought。
6. 后续执行仍可通过 `request_tools(intent)` 更新当前子目标并重新召回工具，下一次模型请求使用更新后的工具集合。发布与算术工具始终可用。

Plan 与图选择每次均产生真实模型请求，检索不额外调用 LLM。结构响应可修正一次，计入相同预算。规划、编译或执行失败时，保留成功观察并回退到完整工具集的 ReAct；所有规划成本和回退原因保留。原始错误记录没有被新运行覆盖。

这是 G-Agent 思路下的独立 Plan、模型角色和有界调度实现，不声称完整复现某篇论文。当前自动图每任务生成，不等于从历史轨迹学习的 motif，也没有自动将本次图晋升到公共经验库。旧 OpenAPI 工具生成、历史读取图和负 motif 模块仍独立存在。

## 模型与并发配置

后端 `.env` 中现有 `LLM_MODEL` / `LLM_BASE_URL` / `LLM_API_KEY` 控制执行模型。新增可选 `PLANNER_MODEL` / `PLANNER_BASE_URL` / `PLANNER_API_KEY` 控制规划角色，未填写的字段继承执行配置。可配置小模型规划、大模型执行；界面只报告实际模型名称及是否不同，不凭名称猜模型规模。

HTTP 仍全部经过 `backend/model_client.py`，两角色均关闭 thinking，OpenRouter 同时关闭 reasoning。`phaseMetrics` 分别记录 plan、graph、execute 请求与 token，失败请求也计入总预算，不返回 usage 时标记不完整。

调度独立限制如下（仅针对新的 TaskRunner，不是所有旧 API 的全局资源限制）：

| 配置 | 默认 | 含义 |
|---|---:|---|
| TASK_RUN_CONCURRENCY | 4 | 同时执行任务数 |
| TASK_MODEL_CONCURRENCY | 4 | 两种模型角色合计请求并发 |
| TASK_READ_CONCURRENCY | 8 | 所有任务共享的读取并发 |

最多 32 个运行中或排队任务。排队等待与执行耗时分开记录。SQLite 只读操作在工作线程执行，使用独立证据上下文，完成后合并；报告等产物顺序执行。ReAct 基线收到批量读取调用时也可并发，不人为削弱基线。取消后已进入线程的只读操作可能短暂完成，但不会修改业务数据或继续写入运行上下文。

测试验证有界并发、跨任务状态隔离、阶段计量、排队/运行取消、动态分页、依赖顺序、检索、非法图拒绝和 ReAct 回退。这里只证明调度机制，尚未进行大规模吞吐压测。

## 使用

任务库 `http://127.0.0.1:5173/#taskbank` 新增 Agent 执行区，可选择 ReAct、Plan + ReAct 或 Plan + AutoTool DAG。可以切换任务连续提交，后台独立排队，查看 Plan、候选工具、读取图、分阶段 token、评分和回退。原先手工工具调试仍不调用模型。

```text
POST /api/taskbank/runs
{"taskId":"finance-payment_totals-01","strategy":"autotool"}

GET  /api/taskbank/runs
GET  /api/taskbank/runs/{id}
POST /api/taskbank/runs/{id}/cancel
```

完整结果保存在 `artifacts/taskbank-runs/<id>.json`。不读取 gold.json 或参考答案作为模型输入。三个模式使用相同任务、工具实现和评分器；后续对照须同时比较 Plan + ReAct，以区分模型规划、工具检索和图执行贡献。
