# 工作区 Workpack 正式 Train 在线协议

日期：2026-09-12。协议 ID：`workspace-workpack-online-full-train-v1`。本协议在 V3 预检之后冻结；V3 是独立诊断，不计入本正式流。

## 冻结范围

- 72 个可追溯工作包来自 `benchmarks/workpacks-v1.json`：财务、客服、技术工单各 24 项；每场景四个工作流，每工作流六个不同实例。
- 正式在线流只使用 48 个 `train` 实例：每工作流第 01–04 个实例。第 05 个为 validation，第 06 个为 test；二者均不更新经验，也不用于当前 Agent 训练流。
- 到达顺序固定为四轮：每轮按 12 个工作流交错出现，确保同工作流实例按 `01 → 02 → 03 → 04` 到达。Baseline 和 RSI 各自看到完全相同的任务顺序，arm 顺序按 pair 交替。
- 每个实例由同一 `WorkspaceManager` 文件解析入口 materialize；任务只接收当前工作区随机生成的表 ID、行 ID 和证据，不携带前一个实例的值。

## 两臂与计量

- Baseline：强 `plan_react`，不进行跨任务学习。
- RSI：`graph_rsi`，每轮完成后才从通过私有结构化校验的 `train` 运行更新此实验专属经验库；下一任务只能使用此前快照的经验。
- 限制固定为 `run_limit=1`、`model_limit=1`、`read_limit=1`。Judge 在 Agent 流结束后另行决定、另列 token 和费用。
- 两臂共享 Parser、工作请求、工具、执行/规划模型设置、预算、报告恢复、硬校验和任务资料。模型端点为分时调用，延迟仅作观察值，不作稳定供应商性能归因。
- 每 pair 前后保存经验快照。恢复不会重新执行已完成 arm 或再次累加已保存经验支持度；服务中断保留 `interrupted`，不会自动拼接或隐式续跑。

## 预运行量级

V3 的 12 任务/臂实际共计 128 次模型请求、986,053 Agent token 和约 1,259,315ms 的串行任务时长。因此本冻结流的执行前量级估算为：96 次 Agent、约 512 次模型请求、约 3,944,212 Agent token、约 5,037 秒（84 分钟）串行任务时长。

这是基于保存的 V3 实际量的估算，不是价格承诺或效率结论；没有可靠单价配置时只报告 token，不虚构美元。任何系统性模型、网络或计量故障会停止后续提交并保留已完成记录。

## 预先固定的解释与平台期规则

主要效率指标为同任务累计 token 节省率：`1 - RSI 累计 token / Baseline 累计 token`。它包含冷启动、规划、执行、恢复和学习引起的模型请求；检索、编译、绑定、维护和持久化耗时单列。失败仍保留在分子和分母中。

平台期仅为描述性检查：四项固定窗口中，只有相邻两个窗口的累计节省率变化绝对值小于 3 个百分点、Fast 覆盖变化小于 10 个百分点且成功率变化为零时，才标为“此有限池可能进入平台期”。该标记不证明理论上限。

没有 Composition、G1/G2 或正向 token 收益时会如实报告；不会降低门槛、插入影子 rollout、按结果改任务或从 validation/test 回写经验。
