# 补充决定：移除惯性分支，优先解决恢复长尾

日期：2026-09-10。来源：用户在讨论 session 明确表示“autotool机制可以删掉，不强求，第三个问题暴露的大量长尾必须解决”。这是新的工作优先级，供执行 session 合入在途设计与 TODO。本文件不表示运行代码已经完成删除或修复。

## 范围调整

- 本轮不再修 AutoTool 的触发入口、不调阈值、不追加惯性收益实验。移除当前 TIG/惯性预测执行分支及其专用配置和活动入口；旧实验记录保留，旧数据不再作为活动经验更新。
- 不要因为文件名叫 `autotool.py` 就整个删除。BM25 工具检索、契约、共享序列化和平台工具封装仍被现有 Plan/图/连接器使用，应按真实依赖保留。
- 保留 G-Agent 的 Plan/Workflow/TinyEdge 和 Motif 执行；跨场景经验隔离错误仍是必须修复的正确性问题。
- 本决定取代 D19 的后续开发优先级；D19 和旧实验仍保留为历史。执行 session 完成后更新对应状态，不把计划写成已经实现。

## 最高优先级：正确且有界的恢复

AutoTool 在旧36任务流中没有执行，因此不是本次额外模型成本的直接来源。重点处理两个已经定位的长尾及其通用故障面：

1. 工具能力匹配：需要记录列表时必须有列表能力，需要支付字段时不能仅凭文本相关性选择其他详情工具。没有可靠来源时交回模型，不能硬猜工具或 ID。
2. 任务语义：原任务约束是权威，Plan 不能将“达到”改成“等于”。避免把不支持的业务判断强行编译成等值过滤，不写具体任务或答案的专用修正规则。
3. 引用格式：根据本次实际观察的证据引用检查或明确反馈格式问题。仅在一一对应且无歧义时允许规范化，并记录转换；缺少证据与格式错误分开，不能为补前缀重读全部记录。
4. 报告修复次数：约束必须覆盖连续 `publish_report` 失败，而不仅覆盖模型停止调用工具后的回复。沿用正在设计的至多一次针对性重提：原稿失败后允许一个有依据的修正，仍不通过则明确失败退出。
5. 循环止损：记录校验错误签名、已知观察和修正进展。相同问题无进展时不能继续相同读取/相同报告循环。单纯提高调用上限不作为修复。
6. 共享正确性修复对基线同样生效；重新检查旧对照兼容性，不能把格式处理或预算变化包装为 RSI 独占收益。

## 验收

- 优先复现并修复 `finance-installments-06` 和 `finance-cancelled_payments-04`，随后用其他正常训练实例检查泛化。
- 两条旧运行保留为负向证据，新运行使用新 ID；不改写其状态、成本或得分。
- 记录实际报告提交次数、重复查询、失败原因、修正依据、总 token/延迟和最终质量。
- 更早终止错误任务只能证明止损有效；必须另外证明原任务能够正确完成，才能宣称修复成功。
- 经验维护错误不能被业务 `completed` 掩盖。学习链路健康和任务正确都满足，才扩大在线流。
- 不恢复旧沙箱，不重新跑全套72次 Agent/Judge 来代替定位。先最小复验，再根据受影响路径安排必要对照。
