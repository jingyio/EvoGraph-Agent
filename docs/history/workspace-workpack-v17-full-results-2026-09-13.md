# Workpack V17 全量在线结果

日期：2026-09-13。原始工件：
`artifacts/workpack-experiments/005ffeb9-964e-42ac-86e9-fb9e8f2212fe/experiment.json`。
该文件不入 Git；本文只记录从保存工件读取的结果，不改写任何历史运行。

## 1. 协议与可比性

- runtime 线：**V17**；控制器模式名仍为 `full_train_v15`，因此本文统一称
  “V17 / `full_train_v15`”，不与已取消的旧 V15 full 混淆。
- 两臂：`plan_react_without_cross_task_learning` 对 `graph_rsi_empty_isolated_experience_train_only`。
- 任务：冻结的 48 个 `train` 工作包，三场景各 16 条，12 个工作流各 4 条不同实例。
  两臂都按相同 manifest 顺序看到任务；每个 arm 串行，
  `run_limit=model_limit=read_limit=1`，pair 内 arm 顺序交替。
- 模型：保存元数据为 `qwen/qwen3.5-27b`。两臂的工具、预算、公共提示、确定性恢复和
  资料解析入口相同；Baseline 不读写跨任务经验，RSI 从独立空经验库开始，仅完成的
  `train` 任务才更新经验。
- 运行时指纹：`executionDigest`
  `58a05bb656b493b013c825ab3180bab1de9a3fbe7c67e813e3af532325e87bc2`。
  全部 96 次 Agent 运行都有保存 usage，`modelTransportRetries=0`；因此不含旧 V15
  cancelled artifact 中不可审计 retry 的问题。
- Judge 未运行，费用与 Agent token 不混合。本结果的质量门槛是每个已启动任务均通过
  私有的结构化事实与证据校验；它不等同于独立自然语言质量评测。

## 2. 质量、成本与延迟

| 指标 | Plan + ReAct | Graph RSI |
|---|---:|---:|
| 通过 / 启动 | 48 / 48 | 48 / 48 |
| Agent token | 2,244,017 | 1,243,546 |
| 模型请求 | 258 | 149 |
| 工具调用 | 422 | 325 |
| 每通过任务 token | 46,750.354 | 25,907.208 |
| P50 / P95 / 最大时长 | 60.335 / 141.685 / 176.215 s | 39.604 / 100.562 / 121.581 s |
| 最大单任务 token | 129,479 | 71,482 |

全量同质量 Agent token 节省率为
`1 - 1,243,546 / 2,244,017 = 44.5839%`；模型请求少 109，超过约 30% 的目标。
延迟为同一模型服务在交替 arm 顺序下的串行观测，能说明这批运行的端到端差值，
不能说明跨时段或其他 provider 的稳定延迟优势。

按场景的 token 节省：财务 38.4175%（976,474 → 601,337），客服 48.4264%
（689,021 → 355,353），技术工单 50.4157%（578,522 → 286,856）。三个场景均通过
私有结构化校验；这不是对生产企业写入流程的验证。

## 3. 在线经验实际改变了什么

RSI 在首轮及一个额外 fallback 任务中形成 12 个初始 Workflow；后续任务实际选择
Fast 35 次，Fallback 13 次。每个 Fast 选择保留了当时的经验快照、选中版本 ID、
来源任务和当前工作区 schema/工具契约绑定。它复用的是结构和参数槽，当前表 ID、
字段和行证据均来自本次工作区，不复用旧业务值。

未观察到 Composition；也未形成 G1/G2 或由正常反馈触发的多代结构修订。因此本轮能证明
“在线积累初始 Workflow 并在后续同类工作包 Fast 复用”，不能宣称 Persistent TinyEdge
组合收益、连续结构进化或多代自我改进。

## 4. 恢复、错误与本地开销

这里统计的是**全部尝试**，不是只统计初次报告：

- Baseline：59 次报告尝试、11 次失败报告尝试、11 个运行进入有界报告恢复；8 次
  `evidence_coverage` 缺口，17 次公开资料范围补齐读取，8 次确定性原报告重提。
- RSI：51 次报告尝试、3 次失败报告尝试、3 个运行进入有界报告恢复；1 次
  `evidence_coverage` 缺口，2 次公开范围补齐读取，1 次原报告重提，1 次公开事实恢复计算。
- 两臂均没有重复报告失败任务、最终缺报告、usage 不完整或 RSI 经验维护错误。
  但并非“没有工具错误”：保存 trace 分别记录了 Baseline 15、RSI 21 次被 runtime
  拒绝或失败的工具尝试，全部保留在成本和可靠性账本中，且没有形成终态任务失败。
- RSI 的 `runtimeOverheadMs` 累计 787.756 ms，另有 lookup、编译、绑定、维护和持久化的
  独立 phase ledger。局部 phase 时间可能嵌套，不能相加后再与端到端时长比较。
  `compositionModelWallMs` 是 fallback 组合尝试的计时字段，不是 Composition 成功；
  以 `learning.composition=0` 为准，不能把该字段计作组合收益或本地零成本。

V17 加入的截止时间终态报告保护只在 Baseline 中触发 1 次。它是两臂共享的可靠性修复，
不是 RSI 学习收益。

## 5. 来源与展示边界

工作包由 Olist、CFPB 和 Zammad GitHub Issues 的公开历史记录重组，经本地工作区文件
解析器和受限只读 JSON Schema 工具访问。它们不是生产企业数据库，也没有付款、发信、
关单或其他外部写入。用户工作台的上传资料存放在独立工作区，不参与本实验经验库。

实验中心 `/#experiments` 直接读取保存的 V17 工件，按任务族展示来源、Fast 使用、同任务
token 曲线、结构化质量和完整恢复账本；图表不写死实验数字。默认 `/#home` 是交互式
工作台，允许上传、提问、执行、下载和同工作区追问，单次用户任务默认
`learning_enabled=False`，不会污染 V17 或历史 Graph RSI 经验。

## 6. 结论与剩余缺口

本工件支持：本固定 48-task train 协议下，Graph RSI 保持私有结构化质量门槛、完整 usage
和有界恢复，并以 44.5839% 更少的 Agent token 完成相同范围。

尚未证明：独立 Judge 或人工文字质量、生产写入能力、通用/同时段延迟优势、Composition
收益、G1/G2 多代结构进化、长期平台期或跨数据源泛化。旧 V12 失败、旧 V15 取消、V4
任务库结果均保留为独立历史工件，不能与本结果拼接。
