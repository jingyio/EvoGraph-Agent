# 三场景 Graph RSI 归因预检结果（2026-09-15）

## 结论

本轮建立了三场景 48 项冻结资产与同机制归因运行线。旧 probe `3fe6c157-0a32-4268-b9bf-3c38e88b6381` 在第 7 对 C10 按旧策略停止：在线 RSI 7/7 通过，不学习图 Agent 6/7。它显示在线学习臂同时获得更高准确率和更低绝对模型开销，但协议只完成 7/12，不能据此发布三场景或48项结论。

当前数据分析默认仍使用金融 12 项 candidate `d02f0ecd-8bb5-4359-94be-e7f7233df6a5`。跨场景运行只进入历史与诊断，不与金融结果拼接。

## 冻结设计

- 资产：`cross-domain-rsi-attribution-v1-48`，题面和附件逐字节复用 `trajectory-review-v3-r3` 的 48 个 train 项。
- 三场景各 16 项；六个连续子簇各 8 项。
- 12 对 probe 固定为 F01/F05/F10/F11、C01/C04/C10/C11、T01/T04/T10/T11。
- 两臂都是 `graph_rsi`；不学习臂每项从空经验冷启动，在线臂从独立空经验开始并只学习此前正常 train 项。
- 模型统一 `qwen/qwen3.5-27b`，thinking 关闭，`run=model=read=1`，单 run 最多 24 次模型请求。
- 任务顺序、附件、题面和评分不在运行中改变；全部失败、超时、工具错误和 token 保留。

## 实现与修复

本轮新增 run-local `granular-compute-v1` 原语：映射行筛选、键集合限制、业务键选择、按键计数、ISO 日期时差比较和异常日期选择。收据保存真实上游依赖，可从成功轨迹编译 `$output` 绑定；不缓存业务答案。

真实 smoke 暴露并修复了三个共享协议问题：

1. C01 的证据范围只覆盖题目实际要求的 `complaints + responses`，不再要求读取无关叙述表。
2. 键限制可直接组合筛选映射、finding 或键控数值，避免为了收据类型转换重复调用模型。
3. 顶层 `selectedIds` 按公开交付契约从原因组业务 ID 去重合并；这只消除重复格式字段，不读取 gold。相关计量字段随后补齐初始化。

旧失败工件没有改写。

## 最终 probe 的机制证据

最终 probe 的在线臂实际图执行 5/7（71.4%），达到局部命中门槛；F05、F10、F11、C04、C10 都记录了历史版本的真实图节点执行。F05、F10、C10 产生候选修订，F05 后续在 F10、F10 后续在 F11、C01 经验后续在 C04/C10 使用，保存工件中可追溯来源 run、父版本和执行节点。

这证明在已经运行的财务与客服前 7 项中存在创建、复用、覆盖修订及后续使用。它没有覆盖技术工单 probe，也没有达到两臂同质量，不能主张三场景普遍收益、48 项可靠性或正式递归进化结论。

## 成本与可靠性边界

最终 probe 的原始绝对量为：

- 不学习图 Agent：1,091,875 token、82 次模型请求、132 次工具调用、32 次工具错误，6/7 通过。
- 在线 RSI：647,952 token、44 次模型请求、138 次工具调用、8 次工具错误，7/7 通过。
- 原始 token 差为 40.66%，串行时长差为 6.16%。

由于不学习臂 C10 失败且 12 对协议未完成，`qualityGate=false`、`costConclusionAllowed=false`。这些差值只说明已发生的运行开销，不能作为同质量效率收益。

## 后续协议

用户确认在线 RSI 准确率高于不学习臂可作为可靠性收益继续验证。新runtime将普通业务失败从提前停止条件中移除，同时保留失败、token、请求、工具错误和串行时长。一个新 `cross_domain_formal` campaign 在运行前冻结全部48项与12+12+24阶段：stage1要求在线RSI 12/12、两臂usage完整、维护正常且真实图执行率至少50%；通过后同一实验自动执行stage2，形成24对候选，不重跑stage1。后续如需48对，只恢复同一experiment与在线经验并追加stage3。`qualityGate` 仍要求两臂全部通过；质量不等时页面只展示准确率和绝对总开销差异，不显示同质量节省率。当前金融12项candidate在新跨场景结果完整通过门槛前继续作为单一发布上下文。

## 2026-09-15 门槛修订

用户进一步明确，扩大实验不要求在线RSI固定12/12，只要求它不比“不学习图Agent”差太多。新campaign在创建时冻结最大相对差为1个任务；usage完整、维护正常和真实图执行率至少50%仍为硬条件。`qualityGate` 继续要求两臂全部通过，因此质量不一致时仍不允许同质量token或latency收益主张。旧campaign按各自原协议保留原状态，不追溯改判。
