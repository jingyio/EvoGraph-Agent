## 已核对的业务结果

财务共保存 4 条分配明细：PAY-001 分配至 INV-001，PAY-002 部分分配至 INV-002，PAY-003 分配至 INV-003 和 INV-006。匹配合计 ¥42,000，剩余应收 ¥24,500；3 张发票清零、1 张部分匹配。疑似重复的 PAY-004/PAY-005 和无引用的 PAY-006 没有被分配。保存 1 个重复流水事项、1 个未匹配事项和 3 个逾期事项，初始快照未被修改。

客服 5 个未关闭工单均有符合技能、可用状态和容量约束的负责人；每个工单保存一份引用适用知识文章的回复草稿，所有草稿 `sent=false`。T-1001、T-1003 两个超时工单登记升级。所有工单状态与初始快照一致，没有新增关闭工单。

落盘记录校验包括：正常结束且存在报告；模型请求数与模型响应事件数一致；供应商用量非空；上述分配明细、异常覆盖、坐席容量、知识来源、未发送和未关闭约束。

## 观察到的不足

1. 财务出现 3 次 `create_finance_case` 参数校验失败：模型将 BANK-1004、BANK-1006 或 CASE-001 放入仅接受发票/回款记录 ID 的 evidenceIds。模型根据错误观察重新调用后完成登记；失败未产生错误写入，但增加请求和 token。当前工具描述没有充分区分“可作为文本依据的业务引用”和“允许放进 evidenceIds 的记录 ID”，后续可改进并单独评估。
2. 财务报告摘要将清零发票数写成“3 张发票清零 + 1 张部分核销 + 1 张清零”，与实际只有 3 张清零不一致。确定性统计和逐张发票表正确；不能据此宣布整份报告完全正确。
3. 客服摘要写了“技术类两名可用坐席”，实际是两名具备技术技能的坐席中只有 A-02 可用，A-04 不可用。实际分派、容量结果及最终答复中的人员状态正确。
4. 模型倾向于将长报告写进 publish_report 的 summary 字段，影响简报的精炼程度；当前尚未实施报告摘要的独立质量校验。
5. 配置服务在请求 `parallel_tool_calls=false` 的情况下仍返回了部分包含多个工具的响应。执行器已按收到的工具列表顺序执行，并逐一回传原始 call ID，未实际并行修改状态。不要假定该兼容服务严格执行此参数。

本次结果证明模型连接和真实 ReAct 工具闭环可用；它不是任务成功率、报告完全正确率或 RSI 收益的 benchmark。后续应保留本次未修改的轨迹，增加任务变体和独立质量评分。
