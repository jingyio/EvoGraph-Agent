# 可视化执行演示

入口 `http://127.0.0.1:5173/#demo`，左侧导航“Agent 执行演示”。React 演示页通过任务库 API 读取后端真实事件，不制造工具调用或模型输出。

## 展示操作

1. 选择场景和一个任务，再选择 Agent A/B。支持 ReAct、Plan + ReAct、Plan + AutoTool、Graph RSI。
2. 点击“并排运行真实任务”，两侧各提交一次该任务，使用现有模型、工具与评分器，自动进入专注模式。可分别停止运行。退出页面不取消后台任务。
3. 实时观察模型请求、工具返回、输入/输出 token、调用数量、错误与图节点状态。模型、图工具、模型调度工具的时间条使用相同相对时间尺度；排队等待另列。
4. 点击任一轨迹事件，展开原始参数、调用 ID、工具返回、模型返回的操作说明或评分。工具 ID 关联保证并发同名调用不会配错结果。工具数据按普通文本呈现，不执行 HTML。
5. 两侧结束后可从头播放、暂停、调整 1–16 倍速度，或拖动时间轴。回放不触发模型/API 业务调用，只读取已保存运行记录。起点不展示最终报告、评分或 token。
6. “本次对照”只在同任务、同执行模型、双方完成且结构化评分通过、用量完整时显示差值。图内消除次数与相对基线的净工具减少次数分别展示。

默认不自动运行模型。首次进入会读取已选任务的最近历史记录；记录为空时需要主动启动或选择其他策略。任务选择和策略保存在浏览器本地，刷新恢复选择并载入最近记录。

## 轨迹协议

`backend/task_runner.py` 为新运行保存 `traceVersion=2`：

- `startedAt` 与逐事件 `elapsedMs`：实际执行时钟，排队等待另列。
- `model_start / model / model_error`：同一 `requestId`，请求开始、响应和异常可关联。只保存模型名、可用工具名、响应公开 content/tool_calls 和 usage，不输出请求凭据或隐藏 reasoning。
- `action / observation`：同一 `callId`，同时记录 `executor` 与 `nodeId`。
- `graph_created`：当时的图结构；后续图事件包含 `nodeId/state`，回放从事件重建状态。
- `evaluation`：报告调用返回的真实结构化评分。
- `finished`：包含最终状态、评分、图维护信息和完整指标快照。
- 每个事件保留当时的 `metrics` 副本，回放不倒灌最终计量。

运行中的详情通过现有 GET API 约每 650 ms 更新，结束即停止轮询。网页轮询不计为业务工具调用；事件快照、网络传输和渲染有正常观测开销，不声称零开销。模型调用前持久化开始事件，异常时保留用量不完整标记。

旧记录仍可回放，但没有调用关联 ID 的观察不强行配对；缺少模型开始时间时只显示时间点，不推测请求时长。历史记录的早期指标由已观察事件累计，终点使用原始最终指标，并显示旧记录提示。

## 验证

- `npm test`：89 个后端测试通过，包括请求未返回时可观测、指标快照不被后续修改、工具 ID 关联和终止事件。
- `npm run test:frontend`：4 个回放语义测试通过，包括时间轴不泄露未来结果、并发乱序返回、模型等待区间、旧记录不伪造时长。
- `npm run build`：TypeScript 与 Vite 构建通过。
- 浏览器验证了实际提交、实时等待与图执行、回放暂停/终点拖动、原始工具返回详情和专注模式布局。
