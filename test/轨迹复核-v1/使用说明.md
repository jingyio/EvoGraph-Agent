# 新财务完整样例与三场景手工输入

每个目录的 `输入附件.json` 可直接上传到工作台，再粘贴同目录 `问题.txt`。
资料来自公开历史记录，`来源.json` 保留原始缓存hash与来源说明。
CFPB提供的是消费者公开叙述摘录，字段标明截断，不是完整客服对话。
GitHub Issues不是企业内部工单。未注入业务异常，也未修改原有test附件。

财务首份资料含12订单、13笔支付、11条商品明细，存在实际缺商品明细订单。
请求明确差额>5分、最大分期>=8、缺失单列、独立原因与证据、BRL显示及仅内部建议。
报告的生成和审核状态须以实际run为准；资料准备不等于任务已运行或通过。

完整冻结资产为三组各8train，另各1validation/1test；具体来源ID和难度特征见
`benchmarks/trajectory-review-v1.json`。实验内部私有评分不属于用户输入，不能上传给Agent。

录制时先展示用户问题与附件，再看本次报告。旧失败必须在轨迹预检页面中保留，
不能拿不同run的成功报告替换失败流程。已有预检页面： http://127.0.0.1:5173/#trajectory 。
